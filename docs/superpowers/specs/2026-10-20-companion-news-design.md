# 0.9.7 定时来信设计

状态：2026-10-20 用户已确认按本方案实施；尚未进入产品实现。执行拆分见 [统一实施计划](../plans/2026-10-20-companion-news-memory.md)。

## 目标与已确认范围

承接 [桌宠三期规划](../../companion-agent.md) 的第二期：用户主动填写兴趣与汇报时间，应用运行或驻留托盘时检索相关新鲜事，由桌宠发送简短卡片，点击阅读完整报告与来源。保持第一期的独立模型配置、默认角色、MCP 工具边界和真实 LangGraph ReAct 循环。第三期占卜继续保留占位。

原约定已经明确：不分析被动键盘输入；配置位于桌宠自定义窗口；复用输入、卡片和详情；提供工作中的友好反馈。此次开发不包含发布、上传、推送或提交。

以下具体产品规则是本设计提出并在此次确认中采用的默认选择；它们不是旧版已实现行为。

## 方案取舍

| 方案 | 优点 | 局限 |
| --- | --- | --- |
| 应用内调度＋持久任务记录（推荐） | 可去重、恢复报告、解释失败；复用现有线程与工具 | 需要增量迁移和异步状态编排 |
| 纯内存 QTimer | 接入最少 | 重启丢失状态，无法可靠识别当天已执行任务 |
| 系统计划任务／独立常驻服务 | 可在主程序退出后执行 | 超出驻留应用的约定，增加安装、权限与生命周期复杂度 |

采用第一种。QTimer 只提供唤醒信号；是否到期由可注入时钟的纯规则决定，是否允许执行由数据库事务核准。进程退出即停止，不注册系统任务、不唤醒电脑。

## 用户体验与默认值

- 「未来来信」变成「定时来信」，保留错落切角布局和雾紫／冰蓝／珊瑚主题。占卜保留第三期提示，不在产品中展示参考网站名称。
- 定时开关默认关闭，只有智能体总开关与来信开关都开启才会自动请求。关闭桌宠总开关也暂停自动汇报；仅隐藏桌宠或主窗口不停止排期。
- 兴趣由用户明确填写，1—5 个，每个最多 40 字，总长不超过 200 字；去除空白与重复项。第一版不从搜索历史推断兴趣，也不读取昵称、统计、练习内容或输入正文。
- 每天一个本地时间，默认 09:00；安静时段默认 22:00—08:00，可关闭。开始与结束相同视为无效并提示修改，支持跨午夜区间。
- 展示下次汇报时间、最近状态、最近报告、手动「现在汇报」与失败后的重试入口。草稿仅保存成功后生效；取消、连接测试不改变排期。
- 轮盘「来信」与右键入口开放：有报告时打开最新来信，没有报告时打开来信配置。手动汇报在来信面板执行，避免一次悬停点击意外调用付费接口。
- 到期任务后台整理，不抢焦点。桌宠可见且未练习时显示可滚动简短卡片；点击打开复用详情。手动搜索仍保留原输入与流式体验。
- 桌宠隐藏或正在练习时保存待读来信，恢复可见且空闲后至多展示最新一封。手动搜索卡片正在使用时不覆盖；完整报告仍可通过来信入口读取。
- 成功与失败的桌宠反应使用既有优先级和减弱动态设置。后台任务不弹输入框、不自动打开详情，也不产生奖励事件。

## 排期与恢复规则

1. 使用本机日历日的日报排期，与统计凌晨 4 点日切分开。记录计划当地日期、计划时刻和实际 UTC 时间；不修改统计日历。
2. 每 30 秒检查脱离数据库的配置／状态快照，单次检查未完成时不堆积。没有到期项不写库。
3. 当日计划时刻落在安静时段内时，顺延至同一当地日期内的安静结束时刻；若需顺延到次日，则跳过本日，按次日自己的排期运行。设置页按同一规则展示下次时间。
4. 只自动受理当前日、有效到期时刻后两小时内的任务。重启或唤醒错过两小时则跳过，不补齐历史日报；恰在窗口内只尝试一项。安静期间不启动自动网络任务，也不弹出自动通知。
5. 自动任务 ID 为 `news:<当地 YYYY-MM-DD>`，数据库唯一约束确保每个日历日最多一个自动任务，修改时间或兴趣不额外生成当天任务。重启／时钟回拨不会重复受理已有 ID；切换时区后仍按当地日期去重，不保证每滚动 24 小时恰好一次。
6. 手动汇报使用独立稳定 UUID，不消费当天自动名额。按钮连点和重试沿用当前 ID；用户明确开始另一封手动来信才创建新 ID。手动操作可在安静时段执行。
7. 自动与主动搜索共享同一个网络准入门；自动任务遇到忙碌在有效窗口内延后检查，不占用名额。事务领取之后、启动前若发生准入竞争，标为未运行并允许同一 ID 再次领取，不算上游失败。
8. 网络开始后失败／取消不算成功，不自动再次调用上游；当日保留状态并允许用户明确重试。超出自动窗口不再自动发起。避免断网或服务错误时循环计费。
9. 配置停用／画像修改会使在途自动任务失效并请求取消。旧配置的迟到结果不推送；已经完成的历史报告保留。网络真正结束前继续持有共享准入。
10. 启动发现前一进程的运行中记录，标为「上次中断」，不自动重复付费请求。重启前已保存完成的报告可直接阅读，已受理展示的通知不再次弹出。

## 模块、契约与线程

| 位置 | 新增／调整职责 |
| --- | --- |
| `app/modules/companion/news.py` | 不可变来信配置／计划／任务／展示契约；兴趣校验、到期／安静时段／下一次时间等纯规则 |
| `app/modules/companion/api.py` | 公开来信规则与持久化服务契约，跨模块只使用该入口 |
| `app/modules/companion/repository.py`、`news_service.py` | companion 拥有任务与报告；工作线程内校验领取／完成／取消／展示状态；仓储不自行提交 |
| `app/storage/db.py`、`session.py` | 新增迁移 3、仓储装配、统一 UnitOfWork；保留旧迁移与 Backup API |
| `app/bootstrap/application.py`、`features.py`、`read_models.py` | 装配异步来信命令与有界只读展示模型，提交后刷新 companion 主题 |
| `app/workflows/companion_news.py` | 编排领取、完成与展示受理的提交；不在工作线程执行网络 |
| `app/integrations/companion_agent/graph.py`、`service.py` | 增加来信请求模式，复用模型／MCP／取消／限额与同一准入门，不另造固定搜索管线 |
| `app/ui/companion/news_controller.py` | Qt 主线程排期协调与 Presenter：唤醒、异步命令、网络 Future、失效 token、通知竞争，不持有 DataSession |
| `agent_settings.py`、`agent_widgets.py`、`agent_controller.py` | 来信配置和状态、轮盘入口、卡片／详情复用、交互协调 |

现有 `CompanionAgentService.search(config, topic, progress)` 保持兼容。增加独立来信请求契约与入口，携带明确任务类型、主动兴趣及检索日期；调用共同的图执行器，避免将冗长指令塞进 200 字话题参数。默认角色仍由 companion 纯规则层装配。

典型流程：Qt 到期判断 → ApplicationWorker 事务核准并提交领取 → 网络线程执行 LangGraph → Qt 接收不可变结果 → ApplicationWorker 事务保存报告及任务完成 → 提交后刷新展示模型 → Qt 按展示资格申请通知 → 通知受理提交后显示短卡片。

数据库只在 ApplicationWorker 使用；网络线程不访问 QWidget，UI 不持有连接。配置变更与退出通过请求 token 作废结果；Qt 不等待未完成 Future。自动与手动请求之间的状态切换不能取消对方或覆盖当前阅读内容。

## 检索质量与报告内容

来信提示词要求基于用户明确兴趣与本次当地日期，搜索近期动态，必要时改写关键词、读取已知来源后再整理；保留默认角色、资料不可信约束与来源编号。工具仍仅允许 `web_search`、`read_webpage`，不扩大文件／系统／任意 URL 权限，不接任意外部 MCP。

摘要包含主要动态、为何与兴趣有关和来源引用。区分检索时间与新闻发布时间：搜索返回没有可靠日期时明确日期未核实，不把检索时间标成发布日期，也不把陈年资料称为今日热点。来源不足或没有相关新动态时明确说明，不用模型记忆补造新闻。模型有工具权限不等于已验证来源真实／时效。

复用既有 6 轮模型、8 次工具、3 次搜索、3 次正文读取、8 来源和合作式 300 秒限额，不按每个兴趣分别启动整套图。已有真实资料但流程未完整完成时可保存带警告报告；没有可引用来源的失败不记为成功来信。继续过滤思考正文，不存 `reasoning_content`、原始 SSE 或工具对话。

## 持久化与提交语义

迁移 3 新增 companion 专有任务表，保存稳定 ID、任务类型、当地计划日期／时刻、配置指纹（排除凭据）、状态、尝试次数、进程运行标识、UTC 创建／完成时间、脱敏失败类别、报告和通知受理时间。状态至少区分等待、运行、完成、失败、取消、中断；完成结果与状态同事务写入。

报告仅持久化有界的主动话题、正文、来源标题／URL／必要摘录、检索时间与警告，不保存 Key、完整配置、私有推理或被动输入。读取时同样检查大小、来源链接协议和 JSON 形状，不能把数据库内容作为可信 HTML。

保存重试使用同一任务 ID 与已生成报告，只重试数据库命令，不重跑模型。重复完成返回原已提交结果；旧 attempt 的回调不能覆盖后一次显式重试。每条报告正文上限 12,000 字，至多 8 个来源，每个沿用现有摘录上限；仅保留最近 30 天且最多 100 条历史终态任务。当天去重记录与在途任务不能被历史清理删除。

通知采用「受理后至多展示一次」：先在事务中标记该报告通知受理，再展示 QWidget。受理提交后进程崩溃可能错过一次弹卡，报告仍在历史中可读；不承诺数据库事务和屏幕绘制之间的严格恰好一次。成功提交前不发完成反馈。安静、隐藏、练习和卡片占用时不提前受理通知。

迁移前用现有在线备份，失败回滚保持旧版本。新安装、0／1／2 版旧库均能按顺序迁移；不通过改初始 schema 冒充增量迁移。

## 验收与验证

自动测试只用隔离数据库、注入时钟和模拟／本地 HTTP 响应，不消耗付费接口。

1. 默认关闭无网络；保存生效／取消无效；兴趣上限、安静区间校验和主题切换一致。
2. 当日到期、跨午夜安静、重启／唤醒宽限、时钟回拨、修改排期去重、手动独立任务；无积压和失败自动请求风暴。
3. 事务领取与重复回调、保存失败原报告重试、不重跑网络、旧 attempt 拒绝、迁移备份／失败回滚、重启中断恢复与历史清理。
4. 使用真实 ApplicationWorker 验证连接线程、提交通知顺序、只读模型更新；网络不占事务、后台不操作 QWidget。
5. 主动搜索与自动任务并发准入；取消后直到网络结束才释放；停用／改配置／退出／更新退出丢弃迟到进度与结果。
6. 卡片不覆盖搜索、隐藏与练习延后、通知先提交后展示、重启不重复弹出、详情读取不再请求模型；小屏／深浅主题／减弱动态布局检查。
7. 来信模式执行真实 LangGraph 和模拟 MCP 行动，验证日期提示、没有来源拒绝成功、警告处理、引用和私有推理过滤。

实现后运行相关 companion／ReAct／UI 测试、架构与真实桌面工作线程测试、`check_architecture.py`、`check_comments.py`，必要时全量回归和 `selftest.py`。构建前补充冻结模块清单与无网络来信自检。版本升至 0.9.7；发布与真实安装验证另按用户明确请求执行，不能把离屏通过写成真实多屏／IME／联网验证。
