# 桌宠记忆页：用户与开发者双视角

状态：2026-10-20 用户已确认按本方案实施。两个板块放在桌宠应用内：普通用户看兴趣与记忆，开发者看来源、结构和代码入口。尚未编写产品代码，执行拆分见 [统一实施计划](../plans/2026-10-20-companion-news-memory.md)。

## 范围与方案

建议在桌宠自定义／智能体配置下增加「记忆」入口，同一页面提供「我的记忆」「开发者」两个标签。相比分别维护两套页面，共用只读模型能保持数量、更新时间和保存结果一致；AOCI 浏览器面板继续作为开发仓库索引的辅助入口。

首版接续 0.9.7 定时来信：明确填写的兴趣、来信偏好与已提交的报告记录可以展示。现有 0.9.6 只有主动搜索和内存报告，不能把内存结果标作已持久保存。通用对话记忆需要后续独立规则，不能由搜索网页自动推断用户偏好。

## 普通用户视角

- 顶部用文字和数量说明「她记住了什么」，分别展示兴趣偏好、来信记录及最近成功保存时间；空状态直说尚无内容，不虚构百分比或学习进度。
- 每张记忆卡显示内容摘要、来源（本人填写／主动保存的来信）、更新时间和保存状态。区分「草稿」「正在保存」「已保存」「保存失败」。失败保留可重试内容，成功提示只能在事务提交后出现。
- 提供查看完整内容、修改兴趣和删除相应记忆的动作。删除明确列出影响，确认后异步提交；失败不先从界面移除。不通过删除来信改动统计、经验或已消费物品。
- 使用现有切角便签、雾紫／冰蓝／珊瑚色和错落布局；较长正文内部滚动，窄窗口改单列，键盘焦点顺序稳定。减弱动态时保留全部状态文字。

## 开发者视角

- 对同一条记录提供脱敏的只读结构：稳定 ID、类型、来源、创建／更新时间、保存版本和实际对应的存储位置／状态。不能展示凭据、私有推理、完整模型配置或被动输入正文。
- 提供「对应代码」列表，指向 companion 公共 API、所属持久化实现及 Presenter；跳转只接受安装中已知的本仓库文件，不让模型或网页构造任意本机路径／命令。
- 源码运行时可提供文件与行定位；冻结安装包没有完整源码时显示模块名称和源码仓库入口，不声称本机存在开发文件。
- AOCI 仓库条目展示职责、关系、契约、约束与当前索引状态，明确它是开发代码认知。可选连接已运行的本机只读面板；普通安装不强制携带 AOCI 进程、Go 工具链或开发工作区。
- 外部提供的索引或记录文字始终按纯文本展示；缺索引、未对齐或无连接时如实呈现，不以旧缓存宣称最新。

## 架构接入

companion API 提供同一组不可变展示记录、类型与来源契约。用户标签和开发者标签消费同一快照，数据读取来自 ApplicationWorker 发布的有界模型；更正与删除通过异步命令和 UnitOfWork。UI 不持有连接，后台不操作 QWidget，网络不占事务。

复用定时来信的配置和报告持久化能力；是否需要新增记忆表由具体数据模型决定，不能仅为两个展示标签增加第二份重复状态。开发侧 AOCI 的 baseline、Ledger 和代码条目留在仓库，与桌宠用户数据目录分开。开发者标签不是额外的数据访问授权。

## 验收

1. 空数据和仅内存报告时不声称已保存；成功保存、失败、重试和重启恢复均显示真实状态。
2. 两个标签选择同一记录，数量、来源与更新时间一致；用户更正／删除提交后同步刷新。
3. 删除取消无影响；失败不提前移除；稳定操作 ID 防止重复写入，保存重试不再请求模型。
4. 开发者信息不含 Key 或私有推理；路径跳转只能访问已知代码入口；安装包无源码有清楚回退。
5. AOCI 不可用／索引未建立／漂移时界面如实说明；不影响普通用户阅读自己的记忆。
6. 离屏检查布局、标签、焦点和异步状态；真实 ApplicationWorker 检查线程与事务；中文输入法、多屏与实际冻结包体验另列人工结果。

两个标签已与 [定时来信设计](2026-10-20-companion-news-design.md) 按同一计划实现并随0.9.7发布，共用冻结快照与稳定记录身份。安装升级证据、实际验证和未验项见 [验证记录](../../validation.md)。
